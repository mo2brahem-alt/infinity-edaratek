# T067 — حدود تشغيل مستقبلي للملفات الخاصة

التفويض الحالي يخص المصدر وCI وDB/files مصطنعة فقط. `REAL_FILES_MIGRATED=0` في staging/production. لا SSH أو فحص تخزين أو قاعدة بيانات أو cache أو DNS أو مزود حقيقي. هذه الوثيقة إجراء مستقبلي وليست أمراً منفذاً أو إذناً بتشغيله. لم يبدأ T071.

قبل أي بيئة حقيقية: PM/operations يحددان البيئة، نطاق البيانات، نسخة المصدر، الشخص المخول، نافذة التنفيذ، ومسار backup خاص. يلزم تفويض مستقل للجرد الفعلي وقراءة البيانات؛ تفويض آخر صريح لنقل/حذف أي نسخة حقيقية أو تعديل serving/cache. لا تفويض إنتاج ضمن هذه الميزة. لا تستخدم اختبارات RefreshDatabase أو migrate:fresh على بيئة مشتركة.

1. راجع نتائج CI والمصدر وبصماته، ثم نفّذ non-destructive smoke مصرحاً به فقط. تحقق من جذور local/school_attachments خارج أي public/alias، وملكية وصلاحيات filesystem. public symlink العام يبقى متاحاً للشعارات؛ لا symlink لأي private root.
2. وثق document roots وphysical directories وsymlinks و/storage و/media-files وأي preview/alias/cache/CDN معروف. يجب إجبار **كلا المسارين** على Laravel قبل shortcuts الخاصة بالملفات/المجلدات الموجودة. قالب tools/testing/private-assets.apache.conf.example وHTTP fixture router تمثيليان، ولم يُثبتا على خادم حقيقي. قواعد المصدر الحالية لا تكفي شهادةً بإعداد Apache/Nginx/Webmin فعلي.
3. جهز backup خاصاً للـDB والملفات والmanifest، وافحص استعادة نسخة مصطنعة مع checksum. لا backup في public ولا rollback يعيد ملفاً خاصاً إلى URL قديم. احصر الملفات اليتيمة/المحذوفة/المفقودة والتعارضات واعزلها للمراجعة، ولا تخمّن مالكاً.
4. بعد التفويض فقط، راجع expand-first manifest migration وخطة عدم الحذف في down. rollback يحتفظ بالجدول والبيانات والملفات الخاصة ومسارات التنزيل والمنع العام، وقد يلزم إصلاح forward آمن بدلاً من الرجوع للكود القديم الذي يخدم public fallbacks.
5. الترحيل dry-run افتراضي؛ PRIVATE_FILE_MIGRATION_ENABLED=false يمنع apply. لا يُفعّل إلا في نطاق بيانات مصرح به مستقلاً. لا سجلات مسارات/أسماء/محتوى أو raw SQL؛ تقارير counts وحالات وأكواد فشل آمنة فقط. معرّف سجل manifest ليس إثبات انتهاء الجرد.
6. للجرد الكبير استخدم دفعات inventory-only مع limit1..500 وoffset/next_offset لكل surface من public/storage/media-files، دون أي نقل أو تبديل metadata أثناء اجتياز الدفعات. أوقف كتّاب public legacy ضمن نافذة محكومة كي لا يتحرك ترتيب الجرد؛ الرفع الجديد يجب أن يكون private قبل النافذة. توثَّق كل surfaces والنتائج، ثم تصالح counts مع metadata والمراجع ومفقودات المصدر. inventory_complete يخص surface الحالي فقط؛ false أو pending/quarantine/conflict تمنع إعلان الاكتمال. prefix صور وحده لا يصنف ملفاً عاماً: يلزم سجل الغرض العام، وprivate reference أو manifest history يتقدمان عليه.
7. استأنف manifests المعروفة بدفعات resume-only بعد إثبات الجرد. لكل ملف: inventory snapshot/hash/size → private copy verified → CAS metadata under row lock → revoke all known public copies → verify private bytes and no anonymous copies. قفل MySQL مشترك ينسق العمال؛ source/destination/metadata change توقف السجل دون حذف آخر نسخة صالحة.
8. اختبر URLs القديمة فعلياً على كل origin/alias وعلى known CDN/proxy، مع مراجعة Content-Type/Content-Disposition ونفي وجود bytes في الردود غير المأذونة. نفّذ cache purge مصرحاً به واثبت عدم إعادة التقديم من cache. HTTP fixture يثبت النموذج المصطنع فقط؛ لا يمكن استعادة نسخة متصفح حصلت على bytes سابقاً، ولا تدّع إزالة تاريخية.
9. تحقق من authorized bytes عبر session وBearer بعد الترحيل، و401/403/404 والسحب الحالي للصلاحية/العلاقة، وmetadata بلا disk/path. لا يكتفي الاختبار بوجود الملف في private disk؛ parent policy وبقاء إبطال public aliases شرطان دائمان.
10. reconciliations نهائية: كل private source معروف له manifest ومراجعة، verified فقط مع bytes سليمة ومنع serving مثبت؛ لا missing/orphan/conflict غير محسوم. راجع idempotent rerun وsource hashes والنسخ العامة المكررة ثم احفظ تقريراً داخلياً خاصاً. أي exposure أو drift أو checksum failure يبقي readiness محجوبة.

التعافي من انقطاع: استأنف من آخر حالة مثبتة؛ لا تعيد public metadata أو bytes. قبل switch تبقى source والنسخة الخاصة المتحققة. بعد switch تبقى private metadata/bytes ويستأنف سحب النسخ العامة. فشل checksum/CAS لا يجيز overwrite أو حذف source. التصحيح اليدوي لحالات quarantine أو تبديل snapshot يحتاج مراجعة النطاق والمالك وbackup، وليس auto-approve أو إعادة ضبط التاريخ.

حتى استكمال الدليل البيئي المصرح به لاحقاً تبقى actual inventory/topology/cache UNCONFIRMED وMOBILE_BACKEND_NOT_READY، بصرف النظر عن نجاح اختبارات Phase5 المحلية. لا إذن ببدء WhatsApp أو Flutter أو نشر أو دمج أو دفع main.

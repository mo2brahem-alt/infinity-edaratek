# تهيئة المسؤول بأمان — T033/T034

أزيلت بيانات المسؤول الثابتة وسلوك updateOrCreate الذي يعيد تعيين كلمة مرور/أدوار حساب موجود. لا تُنسخ القيم القديمة في هذه الأدلة، ولا يُجرى تدوير أو فحص لأي حساب حقيقي.

الـseeder معطل افتراضيًا. التهيئة الأولى تتطلب تفعيلًا صريحًا ومدخلات مشغل محمية في `config/provisioning.php`: بريد صالح واسم وكلمة مرور بطول 16 بايت على الأقل، من متغيرات EDARATEK_ADMIN_PROVISIONING_*. لا واجهة HTTP لهذه المدخلات. لا تُطبع أو تُحفظ في الملفات/الأدلة. بعد عملية تهيئة مخولة مستقلة تُزال المدخلات من البيئة المحمية وتُلغى حالة التفعيل.

إذا كان البريد موجودًا فلا يغير seeder أي كلمة مرور أو دور أو حالة أو بيانات شخصية، حتى إن كان الحساب غير مسؤول أو غير نشط. المستخدم الجديد فقط يُنشأ بكلمة مرور مجزأة ودور super_admin ضمن transaction. إعادة التشغيل لا تعيد تعيين حساب قائم. المدخلات الناقصة توقف العملية برسالة عامة دون نسخ القيم.

SafeAdminSeederTest يستخدم قيمًا عشوائية مؤقتة في الذاكرة فقط ويثبت التوقف الافتراضي، التهيئة الصريحة، التجزئة، الحفاظ على حساب موجود وعدم ترقيته أو تفعيله، وإعادة التشغيل. اختبار AccountApprovalFlow القديم الذي كان يفرض إنشاء هوية ثابتة استبدل بفحص أن غياب تهيئة صريحة لا ينشئ أي حساب؛ هذا تغيير أمني مقصود، مع تغطية أقوى لمسار الإنشاء المشروع.

لا migration أو تغيير بيانات مشتركة أو تشغيل seeder ضد المضيف أو staging/production. إثبات H03 يخص المصدر والـfixtures فقط؛ الاستخدام التاريخي الحي يظل غير مفحوص.

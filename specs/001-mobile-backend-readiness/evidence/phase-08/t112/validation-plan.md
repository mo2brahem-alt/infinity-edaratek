## طريقة التنفيذ

1. توثيق المصدر والنسخة والوصول المتاح دون طباعة أسرار. Workflow الحالي ينشر main إلى `/home/test/public_html` ويستخدم SERVER_HOST/USER/PASS؛ ليس قناة تحقق ولا يثبت النسخة المنشورة أو إعداد vhost. لا يُشغّل.
2. HTTP محدود للمضيف المصرح فقط، TLS عادي، لا اتباع redirects، لا credentials، لا تخمين IDs حقيقية. `/up` و`/api/v1/me` وروابط QA غير الموجودة يمكن أن تثبت reachability فقط؛ 404 لملف غير موجود لا يثبت منع ملف حساس موجود.
3. إن توفر اتصال عمليات موثوق: تحقق read-only من هوية vhost/المسار/المستخدم/النسخة؛ ثم effective allowlisted storage/cache/debug config، aliases/permissions، وإثبات QA مأذون/غير مأذون. لا dump لـ.env أو config cache أو private contents، ولا migrate/cache-clear/flush/storage:link/chmod أو إنشاء aliases.
4. أي QA artifact أو cache key يحتاج تحقق العزل أولاً، ويُحذف فقط ما أنشأه التحقق. لا workers/queues أو providers أو اختبارات RefreshDatabase على staging.
5. إن تعذر الوصول، تُسجل القيم UNKNOWN، وتبقى H01/H05/T112 BLOCKED. لا تعيد الاختبارات المصطنعة لإخفاء غياب الدليل. إن أُغلق T112 فعليًا، تُعاد suites المركزة/الانحدار/العقد والكامل وفق طلب PM.

البيانات الآمنة الحالية للوصول: يوجد ملف SSH config دون مدخل مرتبط بالمضيف/المشروع، لا SSH_AUTH_SOCK أو SERVER_*/STAGING_SSH_* محمّلة في الجلسة. API GitHub أعاد أسماء SERVER_HOST/SERVER_USER/SERVER_PASS فقط؛ قيمها غير مقروءة ولم تُطلب أو تُستخرج. طُلب من PM اسم اتصال معدّ مسبقًا أو طريقة وصول موثوقة دون إرسال أسرار.

# Phase6 supported-channel design and retirement review

PM2026-11-09 permanently removes WhatsApp. This is removal of an active product dependency, not a disabled live integration. The source of truth is [notification-policy](../../../../docs/notification-policy.md); see [original requirements](original-requirements.md) and [dispositions](scope-decision.md).

Business services (account approval, subscription, supervision, tickets and onboarding) continue through NotificationService into the existing notifications table. Existing web consumers poll the owner-scoped controller. The change removes its injected retired service and enqueue fan-out, without changing payloads, recipients, routing hints or browser response semantics. Existing notification persistence is the supported in-app path. No push transport/device registration or native notification endpoint is introduced: these are not required by this foundation contract. Later API contract work remains Phase7.

The six historical local webhook/phone-verification routes retain their names and existing middleware but now return fixed HTTP410, code WHATSAPP_REMOVED, private/no-store, no input reflection, no service resolution or database mutation. Old callbacks cannot advance message state. Contact fields and phone-change verification invalidation remain. An inbox notification is not substituted for proof of phone ownership.

The historical transport method contains only a fixed exception; configured() is always false. Its HTTP implementation is removed. Both serialized job classes keep class names/constructor compatibility but handle/failed have no I/O or state mutation. Notification and OTP services reject their old entry paths unconditionally. Config cannot reenable the channel. Historical models, tables, claims, algorithms and test source remain for audit/compatibility; there is no new control schema, switch command, OTP budget feature, state rewrite, resend or historical-data purge.

Source inspection covers the inert job and direct transport boundaries. The active tests exercise app/web behavior and local retirement responses with HTTP and queue fakes, never delivery or historical-job execution. Retired admission race/HMAC/delivery tests are superseded rather than claimed passing. This avoids treating removed functionality as an acceptance dependency.

Only tests/Feature/WhatsAppIntegrationTest.php is excluded in the two suite configurations. Its SHA256 is preserved by a static, non-autoloading scope probe. There were33 methods with one9-row provider:41 static cases. The two unrelated methods (normalization9, phone-change invalidation1) are relocated verbatim to PhoneStateCompatibilityTest and executed. The31 obsolete product cases are classified superseded, not passed, failed or runtime-skipped. New active policy tests add8. Expected full count:670-41+10+8=647. No broad group is excluded; the known Excel failure remains visible.

Operational limit: this is reviewed source and disposable CI, not a change to a running deployment. Processes already loaded with pre-change code are not replaced here, nor can already-started sends be recalled. Any future separately approved rollout must stop/restart old workers; this phase neither inspects nor resumes real queues, providers, staging or production. No assertion that deployed systems have changed is made. Actual aliases/CDN remain UNKNOWN.
